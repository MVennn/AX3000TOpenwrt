**守护新增 AI API 数据面探活；备份修剪修掉三处真问题并接管 /root/backup；高频闪存写入迁到 tmpfs。**

遇到问题、想要新功能，到 [Issues](https://github.com/MVennn/AX3000TOpenwrt/issues/new/choose) 反馈 —— 带上设备型号、固件版本与相关日志。

## 本版内容

**守护**

- 新增 `guardian.sh` AI API 数据面探活 —— 每轮对 `🤖 AI接口` 的当前节点打一次真实数据面探测（不带 key，401/403 也证明链路通，只有连不上才算坏），「面板 alive、健康检查也过、数据面已死」的节点会写 `WARN`。只告警、不写 `fixed`，重选交给该组的 60 秒复测。

**备份**

- 修复 `backup-prune.sh` 三处真问题：总量超限原来**先删最新**（方向反了，删的是新文件、留的是最旧垃圾）、/tmp 写满时 scratch 建不出来会静默猝死整个脚本、收到 INT/TERM 只清锁不退出会继续跑完；现在最旧先删、故障降级续跑、信号干净退出。
- `backup-prune.sh` 接管 `/root/backup` —— 原来只管 `/root/final-backup`，「改前 cp 一份」的副本只进不出会重新堆积；现在两段同套阈值（同 stem 只留最新 1、`pre-*` 留最近 3、超限先删最旧），锚点（sysupgrade.conf、主题包、证书、`.keep` 名单、180 分钟内新写入）一律不删。

**闪存**

- `tmp-watch.sh` 的增速状态文件迁到 `/tmp`（tmpfs）—— 原来每 5 分钟整写一次闪存（288 次/天）；告警路径、阈值、日志格式一行未动，重启丢失等同开机首轮、不会误报。

**仓库**

- `check-secrets.py` / `check-docs.py` 同步系列仓已修的守卫漏报与误报（混行豁免整行放行、同行多命中只报首个、`--all` 不遵循忽略规则、BOM/跨盘符边界等）；本仓分叉差异保留。
