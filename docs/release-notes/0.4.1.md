**守护与恢复脚本的一轮审查修复：锁、探针、恢复门控全部补上，设备不再会因为一次异常退出而静默失效。**

遇到问题、想要新功能，到 [Issues](https://github.com/MVennn/AX3000TOpenwrt/issues/new/choose) 反馈 —— 带上设备型号、固件版本与相关日志。

## 本版内容

**守护**

- 修复 `dest-guard.sh` 的陈旧锁回收 —— 锁目录每轮都会写 `ts`，原来只 `rmdir` 必然失败；进程被强杀后站点守卫会永久静默停摆。现在先删文件再回收目录，失败会留 `ALERT`。
- 修复 健康探测 —— 通用出口与干净出口原来只看耗时，节点被封时的「快速失败」（502 / 连接被拒）会被当成健康。现在同时看 HTTP 状态码，非 2xx/3xx 一律按劣化处理。
- 修复 印度-优化 的判定矛盾 —— 它已是干净出口兜底候选（实测 cc=IN），但坏节点清单仍把它判坏，两套逻辑会互相扳动；已按新实测移出坏清单。
- 修复 `resolve_clean_node` 的裸 `curl` —— 统一走脚本内的 `$CURL`，最小环境下也能取到组成员。

**恢复**

- 修复 `recover-now.sh` 的 DNS 劫持门控 —— 核心 30 秒未就绪时不再无条件重载含 DNS 劫持的 `googleroute`，避免恢复脚本自己复现「连上 WiFi 没网」。
- 修复 `recover-run.ps1` —— Windows PowerShell 5.1 下 ssh 的第一条 stderr 不再终止整个恢复流程。
- 修复 `askpass.sh` —— 空的 `.router-password` 不再吐出空口令。
- 修复 `core-upgrade.sh` 回滚 —— 保留升级前用户自定义的 `custcorelink`，不再一律清空。

**仓库**

- 修复 `bootfix.sh` —— awk 插入不再给 `guardian.sh` 头部塞空行（shebang 保持在首行）。
- 修复 `check-vault-not-staged.py` / `check-secrets.py` —— git 异常时不再打「假绿」；CI 检出改为完整历史，`--all` 能真正扫到历史提交。
