# 硬件与固件基线

> **一句话**：参考设备是什么、跑在什么固件上、网络是怎么接的 ——
> 每一条都带**来源与时点**，因为同一项在不同时点是不同的值。

读这份之前先知道一件事：**这些数字全是实测的，不是查手册得来的**。
换固件、换硬件、换订阅之后**必须重新验证**，不能拿旧数字当现状。

## 2. 固件与内核

| 项 | 值 | 来源 | 时点 |
|---|---|---|---|
| 固件 | **OpenWrt 25.12.6**（`r33311-981c978eff`，官方 ROM） | 第一轮基线审计 | 2026-10-19 |
| 内核 | **6.12.112** | 第一轮基线审计 | 2026-10-19 |
| 防火墙 | `fw4` + nftables；`wan` 的 input / forward 均 REJECT | 第一轮基线审计 | 2026-10-19 |
| 流量卸载 | 软 / 硬 offload **均开**；flowtable 设备集 = `lan2,lan3,lan4,phy0-ap0,phy1-ap0,wan` | 第八轮全量复审（设备集与 `fw4 print` 对齐） | 2026-10-20 |
| 拥塞控制 | `tcp_congestion_control = **cubic**`，**无 BBR** | 第一轮基线审计 | 2026-10-19 |
| 调度器 | `cubic + fq_codel`（无需改） | 第八轮性能复审 | 2026-10-20 |
| 交换 / 内存 | 无 swap、无 zram；`nf_conntrack_max = 15360`（实际 869–1353） | 第八轮性能复审 | 2026-10-20 |
| 关键 sysctl | `net.core.netdev_max_backlog` 1000 → **2048**（5G RX 队列曾溢出 9960 次）；`net.ipv4.tcp_slow_start_after_idle` 1 → **0** | 第十轮加固 | 2026-10-20 |

**BBR 说明**：内核里**没有** BBR。第八轮把它列入「伪问题（已否）」——
参考设备链路无高 BDP 场景，cubic + fq_codel 够用，故未安装、未启用。

**SQM 说明**（设备事实，但有个时点差）：
包**已安装**，但 `enabled = 0`；第一轮审计（2026-10-19）记录它的 `interface`
写的是 **`eth1`**，而实际 WAN 设备名是 **`wan`** ⇒ 即便打开也不会生效（死配置）。
第十轮（2026-10-20）已把 `interface` 改成 `wan`、`download` 85000 → 190000、
`upload` → 20000，**但 `enabled` 仍保持 0** —— 行为零变化，
只是防止将来误开时用错接口 / 限错速。

## 3. 网络拓扑

> 下表是**参考设备**的示例值。换一台设备、换一个运营商或换一层网络拓扑，
> 这些值都会变 —— 用之前先在自己的设备上核对。

| 项 | 值 | 来源 | 时点 |
|---|---|---|---|
| LAN | `10.0.0.1/24`，`br-lan` = `lan2 + lan3 + lan4` | 第一轮基线审计 | 2026-10-19 |
| WAN | `192.168.1.2/24`（DHCP），MTU **1480** | 第一轮基线审计 / 第十轮修正 | 2026-10-19 / 2026-10-20 |
| 默认路由 | `192.168.1.1`（上级路由器） | 第一轮基线审计 | 2026-10-19 |
| **双层 NAT** | 参考设备 WAN 在上级 `192.168.1.1` **之后** —— 入站要穿两层 NAT，端口转发要写两遍 | 第一轮基线审计 | 2026-10-19 |
| 真实路径 MTU | **1484**（设备原先配的 1500 是错的；TCP 靠 PMTUD 侥幸存活，**UDP 一律黑洞**） | 第八轮全量复审（独立复核） | 2026-10-20 |
| IPv6 | `<YOUR-IPV6-PD>`（运营商 PD 委派，无 NAT66） | 第一轮基线审计 | 2026-10-19 |
| DHCP 池 / 租期 | `10.0.0.25` – `10.0.0.224` / 12 小时 | 第八轮全量复审 | 2026-10-20 |
| 代理栈 | ShellCrash + mihomo **v1.19.28**，**Redir** 模式；透明端口 `7890`（mixed）/ `7892`（redir）；控制 API `127.0.0.1:9999`（带密钥） | 第一轮基线审计 / 第八轮 | 2026-10-19 / 2026-10-20 |
| DNS | LAN 客户端的 53 端口被 nft 劫持到 mihomo `:1053`（fake-ip）；dnsmasq 只服务路由器自身 | 第一轮基线审计 | 2026-10-19 |

> **MTU 1480 是有意为之**（第十轮修正）：真实路径 1484，扣掉封装留 1480。
> 改回 1500 会让 UDP 重新掉进黑洞。

| 项 | 值 | 来源 | 时点 |
|---|---|---|---|

## 5. 存储

| 项 | 值 | 来源 | 时点 |
|---|---|---|---|
| overlay 分区总量 | **57.5 MB** | 第一轮基线审计 | 2026-10-19 |
| overlay 占用（早） | **23.1 MB / 57.5 MB（40%）**（开工前是 34.6 MB / 60%） | 夜间作业最终状态 | 2026-10-20 05:10 前后 |
| overlay 占用（后） | **36,392 KB / 58,832 KB（65%）**，余 19,392 KB | 内存 / 存储占用审计（5 子代理并行） | **2026-10-20 15:00** |
| `du` vs `df` | **`du` 是逻辑值，高估约 2.16×**（UBIFS 压缩）—— 判断余量一律以 `df` 为准 | 同上 | 2026-10-20 15:00 |
| `/tmp` | tmpfs，**无 `size=`** → 上限 ≈ RAM/2 = **119 MB**，直接吃内存 | 第一轮基线审计 / 第十轮 | 2026-10-19 / 2026-10-20 |
| `/var` | **指向 `/tmp` 的相对软链**（`/var -> tmp`） | 第十轮（踩坑后确认） | 2026-10-20 |
| mihomo 运行配置 | `config.yaml` 740,216 B / **13,106** 条规则（其中 **9,631** 条内联 IP-CIDR） | 内存 / 存储审计 | 2026-10-20 15:00 |
| syslog | `/overlay/log/messages`，`log_size=2048`，约 **4 MB/天** 写闪存 | 第十轮加固 / 存储审计 | 2026-10-20 |

涨的主要来源是内存审计期间拉回本机的诊断产物与订阅原始文件。
处置口径见 [MAINTENANCE.md](MAINTENANCE.md)。
